# 标注规则 v1.0

## 动作粒度

以“围绕一个明确数学目标，采用具体方法和关键参数的一次尝试”为单位。目标、方法或关键参数改变，或产生可独立使用的中间数学结果时切分；同一尝试中的连续实现、工具调用和检查合并记录。重复执行分别留痕，展示时可聚合为同一动作类型。

动作描述应能回答“为了什么，使用什么方法，关键参数是什么”。例如写“搜索二次多项式系数，使目标式成为平方和”，不要仅写“运行 Python”。同一次批量搜索若枚举了有独立结果的不同方法/关键参数，应拆为多个动作实例，共用调用证据，并记录批内位置；不得按工具调用数量直接决定动作数量。未观察到的批内细节不反推出来。

## 状态粒度

状态由“当前数学表示、候选解／证明、已建立结论和待解决目标”构成；这些内容发生实质变化才新增状态，数学内容等价则复用已有状态。换搜索方向、搜索未找到、编译反馈本身不新增状态，作为动作及观察保留；只有它们实际改变了上述数学内容，才记录状态转移。

“尚未证明”不能写成“已建立”。明确区分假设、猜想与已证结论；假设及适用约束写入 `representation` 或相关结论文本。对于非数学任务，在相同四元组中声明对应的任务表示、候选产物、已确认事实与剩余目标。

相同输入上的三次未成功搜索都是从同一状态出发的自环。若一次失败得到反例并据此排除了候选解，则候选或已有结论变化，可以产生新状态。一个公开提出但尚未实现的方法仅作为动作记录，只有形成具体的新候选证明内容时才改变状态。

编译/验证期间候选内容未变化，则只记录观察，可附于相应动作和状态；独立验证可记录自环动作。最终验证通过只标记该状态的 `acceptance=passed`。建立完整候选时，其数学待解目标可已清空，但验收仍为 `unverified`；正式验收单独记录。

## 相似状态与等价归约

在同一问题、同一切分粒度下，比较数学表示、候选解／证明、已建立结论与待解目标。内容接近的状态作为归约候选；只有这些内容数学上等价，才允许合并。

忽略变量重命名、表达顺序和有依据的等价改写，逐项检查是否存在实质差异。新增或缺失证书、假设约束不同、剩余目标不同、候选证明发生实质变化，都不能直接合并；证据不足时保留独立节点。LLM 可以提出相似候选，但合并需要明确的等价依据。

每次比较记录四个分量的判定和证据；缺失内容视为未知。哈希相等只能证明被哈希快照相同，不能证明未记录内容相同；浮点近似相等不能代替符号等价。不要按“解出了同一道题”合并不同证明路线。

执行归约时，选择稳定的 canonical ID，把边端点与观察主体映射过去，并将 alias 直接映射到 canonical ID，不保留 alias 链。保持原动作实例 ID；若两个端点归为同一状态，转移变为 `unchanged`，原标签仍保留在归约前图。动作类型、顺序、证据、成本和观察不能丢失。只有等价且验收覆盖同一候选快照时才共享验收标签，冲突结果保留并说明时间/范围；无法确认时不要合并。

## 证据、范围与顺序

- 用来源文件指纹、行号、调用 ID、session/parent 信息追溯。观察到“没有找到”与证明“不存在”不同。
- 工具 exit code 是执行反馈，不自动等于数学成败；正常退出也可能是搜索未找到。
- 每个被标准化的可观察事件必须在覆盖表中被标注、说明排除原因或标为未解决。元数据和隐藏推理块另列排除计数。所谓“全部动作”仅限指定来源中可观察、可辨认的动作。
- 不同线程的时间戳不自动构成因果依赖。图上的边必须对应实际状态转移；数学依赖不能冒充执行转移。动作因果关系不明时标未知，不能为了连图虚构父节点。
- 子任务局部状态与主任务完整状态不得无条件等同。必要时分图，在说明中记录贡献交付；只有观察到接收并整合才建立主任务的新状态。
- 时长/token 未知用 `null`；证据时间间隔不自动等于耗时。批量调用不平均分摊成本，同一证据不能因被多条边引用而重复累加。

## 展示规则

逻辑节点仅为 solution states，逻辑边为动作实例；动作框只是边的展开。自环可紧凑表示为“状态不变”。分支按同一起点和方法分组，共同结果允许合流。标题突出数学内容，工具名与执行者放到详情。

重复实例只有在起终点、完整动作定义、effect 和 outcome 全部相同时，才能在界面折叠为一个动作框，显示次数并可展开全部实例。不同结果不可折叠。绘图程序不能合并状态、删失败边或按标题推断拓扑。
